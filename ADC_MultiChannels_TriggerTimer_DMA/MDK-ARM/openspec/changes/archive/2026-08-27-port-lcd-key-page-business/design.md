## Context

当前 PY32F031 工程已经裁剪为 Flash 烧录业务与可复用驱动层。量产示例中的 LCD 页面代码位于另一 MCU 平台的 `main.c`，其中业务状态机、Flash 资源表和渲染策略可复用，但 USI/SPI 初始化、PB3 按键和 DMA 半传输并发方式不能直接复制。当前 W25Q 使用 SPI1 PB3/PB4/PB5 和 DMA1 Channel2/3，LCD 使用 SPI2 PA0/PA10 与 DMA1 Channel3，因此两个设备的数据阶段必须串行。

## Goals / Non-Goals

**Goals:**

- 将示例中的 LCD 页面、动画、数字叠加和按键切换逻辑封装到新的应用模块。
- 保持现有 LCD、W25Q、SPI、I²C、UART 驱动 API、引脚和初始化顺序不变。
- 使用零值业务快照完成显示链路验证，并为后续 I²C 数据接入保留清晰边界。
- 保持 Flash 烧录宏和烧录实现不变，通过编译期开关隔离两种业务模式。

**Non-Goals:**

- 本阶段不读取或解析 I²C 从设备数据。
- 不迁移示例 MCU 的时钟、UART、USI/SPI、I²C 初始化和中断实现。
- 不修改 Flash 图片布局、LCD 方向、W25Q/LCD 驱动公开接口或 Flash 烧录协议。
- 不修复已有中文注释乱码。

## Decisions

1. **业务逻辑放入单一独立模块。** 新模块只公开 `APP_LCD_KeyPage_Run()`，内部拥有页面状态、资源描述符、4096 字节静态图像缓冲区、按键消抖和渲染辅助函数。`main.c` 只包含头文件、互斥检查及宏控制的一次入口调用。
2. **两个业务宏编译期互斥。** `ENABLE_LCD_KEY_PAGE_MODE` 默认开启；`ENABLE_UART_FLASH_LOADER` 的定义位置和值不变。两者同时为真时通过 `#error` 阻止构建，避免 UART、Flash、DMA 和大缓冲区所有权不明确。
3. **按键改用 PB2。** PB3 已属于 W25Q SPI1 SCK，PB2 当前无驱动占用。PB2 配置为下拉输入、高电平有效，保持示例的 50 ms 稳定时间和 150 ms 触发间隔。
4. **零值快照代替 I²C。** 初始化时将八路端口标记为关闭，端口值、温度、合计值和序号清零；模块不调用任何 `APP_I2C_*Read*` 接口。后续 I²C 接入只需更新快照，不改变渲染状态机。
5. **存储读取和显示发送严格串行。** 每块数据先使用 `W25QXX_Read()` 完整读入缓冲区，再调用 `ST7789_WriteDataBlock()`。不使用示例的 W25Q 半传输回调，因为 LCD DMA 会重新映射同一 DMA1 Channel3。
6. **资源长度与 Flash 槽分离。** 完整屏幕只发送 `ST7789_FRAME_BYTES`，数字资源跳过示例定义的 8 字节头，不能把扇区填充数据送入 LCD。
7. **保持当前驱动初始化。** `main.c` 继续初始化 W25Q、UART、软件 I²C、SPI2 和 ST7789；业务模块不重复初始化这些驱动，只初始化 PB2 和自身状态。

## Risks / Trade-offs

- [阻塞式 W25Q 读取比示例 DMA 流水慢] → 本阶段优先保证共享 DMA 所有权正确；页面功能确认后可另建变更实现完整块完成后的串行 DMA 优化。
- [4096 字节缓冲区压缩 RAM 余量] → 使用静态分配并通过 Keil MAP 同时检查 RW/ZI、栈空间和 8 KB RAM 边界。
- [Flash 中资源未按示例地址烧录] → 构建只能证明代码链路，板级验收需确认启动图和各页面资源正确。
- [示例代码来自不同显示方向] → 保持当前 `ST7789_ROTATION=90U`，板测重点检查坐标、数字覆盖区域和图像方向。
- [当前工作区已有未提交修改] → 仅修改明确目标文件，不回退或格式化现有改动，并在最终差异中单独核对。

## Migration Plan

1. 建立并严格校验 OpenSpec 提案、设计、规格和任务。
2. 新增 LCD 页面业务模块并加入 Keil 工程，再以最小改动连接 `main.c`。
3. 执行静态资源、引脚、宏、I²C 调用和共享 DMA 检查。
4. 执行 Keil 全量构建和 MAP 预算检查，记录需要实板完成的验收项。
5. 同步主规格并归档变更。回滚时移除新业务模块和工程项，并撤销 `main.c/main.h` 的新增引用，不触碰既有驱动及 Flash Loader。

## Open Questions

无。PB2、零数据策略、阻塞读取路径和业务宏默认值均已确认。
